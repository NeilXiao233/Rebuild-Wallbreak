# 从原实现恢复可读行为

## 按问题选择证据

- 资产身份/默认参数：原序列化字段、GUID/fileID、库类型/程序集、原包内实际对象。
- 控制流/状态与副作用：原托管方法或原生方法完整 CFG/数据流、字段偏移、调用方与委托绑定；高层伪代码要能回到相关指令。
- 运行条件：同版原包的对象状态、日志/捕获；记下 API、设备、存档、阶段、触发方式。
- 原导出可能漏设置、误导引用或只给空壳。运行输出也不能唯一决定内部实现。互相印证，冲突保留，不选方便的一方。

复用已有经过字节核验的原生视图。只有具体方法缺分支、交叉引用或必要依赖时才扩大反编译范围；不默认安装新工具或全量反复分析。

## 方法契约

选定方法和其直接依赖，记录足够第三方复核的信息：

| 内容 | 要回答的问题 |
|---|---|
| 身份 | 原二进制哈希、方法地址/类型签名、字段偏移与证据定位是什么？ |
| 输入 | 调用方、前置状态、参数、数据来源、有效平台/配置分支是什么？ |
| 接收者 | 对谁调用方法、写谁的字段/Transform？字段名相似是否属于不同根节点？ |
| 控制流 | 失败返回、早退、epsilon/normalize、范围边界、异常路径与返回值是什么？ |
| 副作用 | 哪些状态、订阅、对象、保存键被修改，顺序如何？ |
| 生命周期 | 谁创建/初始化/启用/取消/销毁？协程/Task 何时继续或终止？ |
| 现状 | 当前实现相同点与差异，证据强度，仍未知的分支是什么？ |

不要为每个无关访问器写长篇合同；在高影响或高不确定工作单元使用。复原分支表比逐句翻译工具临时变量更有用。

## 从独立候选到正式消费者

已有 policy/snapshot、纯 C# 模块或单独测试项目时，追踪：原方法证据 → 候选契约 → 输入/输出适配 → 正式类的方法与调用方 → 实际构建与运行。可在原类内转写、内联或合并，不要求文件字节相同、保留候选类名；没有同名引用不证明未集成，找到同名引用也不证明已正确接入。

检查候选测试由谁提供布尔值、委托与快照。人工给定 `hasTarget=true` 或清理回调，只证明该输入下的局部规则；正式调用方的目标筛选、Unity Object 已销毁判空、生命周期、时间推进及副作用仍需单独绑定。只恢复对象清理，不自动覆盖 Animator 触发、AnimationEvent 与粒子回收。优先为高影响跨层接口记录对应，避免建立无实际消费者的独立“已恢复方法”集合。

## 最容易漏掉的有效语义

- **字段接收者**：缩放模型子节点与缩放容器根节点不是同一操作；字段偏移、对象来源与最终接收者必须连起来。
- **父子/空间**：SetParent 的 worldPositionStays、local/worldPosition、bounds 空间、矩阵方向、旋转顺序、非均匀缩放。
- **回调绑定**：属性 setter 赋值与 `+=`/追加不同；DOTween 后一次 OnComplete 覆盖前一次，不要凭早前出现的委托决定最终副作用。
- **编译降低**：IEnumerator/async 状态机承载实际流程；只还原公开方法签名或返回 default，不能算恢复。检查 yield/await、取消、异常和最后清理。
- **求值/边界**：短路、整数溢出、浮点精度、等号边界、epsilon、NaN、排序稳定性仅在原行为实际依赖时保持，不“顺手改良”。
- **订阅与初始化**：诊断 bootstrap 的登记、静态单例和人工注入可能掩盖正式 Awake/Init 漏接；必须回到原入口检查。
- **真实库身份**：namespace/类名相同不等于同一实现。核对 asmdef/程序集、MonoScript localFileID/GUID 与有效版本；不必逐个重写成熟库所有方法。
- **保存与重启**：内存状态正确不等于键、类型、保存时机、迁移和冷启读取正确。使用隔离测试存档，避免污染用户已有进度。

## 实现可读性

先定义已证实的行为，再使用普通 C# 方法、明确类型、语义命名、合适的状态模型表达。允许把编译器多余跳转改成 if/循环，但在契约中保留与证据的对应。不要对无法确认的分支编故事。

不要将第三方代码、解析工具输出、诊断驱动与正式业务源码混为一层。需要诊断接口时，隔离并标明调用边界；正式行为仍由原启动与原组件图驱动。

若用户明确排除广告/支付 SDK：在对应窄接口模拟完成/成功或跳过展示，保留调用顺序、奖励、状态变化与 UI 回调。不要把真实 SDK 操作列为核心关卡门槛，也不要据此将整个结算方法留空。若当前恢复缺口与该接口无关，先推进主链。
