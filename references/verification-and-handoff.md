# 验证、缺口账本与交接

沿用项目已有 control/任务卡/证据结构，不创建第二个状态源。没有现成格式时，采用下列最小字段；不要求建立新系统或全量填表才开始恢复。

## 工作单元与证据

| 字段 | 内容 |
|---|---|
| id / scope | 目标方法/渲染链/状态转换及触发条件 |
| original_evidence | 原输入哈希、方法地址/字段偏移或资产 GUID、source_ref 与行/片段 |
| original_contract | 分支、接收者、坐标空间、时序、副作用与有效回调 |
| current_gap | 当前文件位置、可核验差异、已证实/推断/运行时未验证 |
| dependencies | 真正阻塞此判断的输入；可独立推进部分 |
| change | 拟改或已改文件、理由、保持的原身份与配置 |
| validation | 命令/夹具/运行步骤、条件、预期/实际、失败记录与复验方式 |
| versions | 源码清单/哈希、构建、实际包哈希/包名、运行设备/API/存档/节点 |
| result / limits | 每层结果、未覆盖分支、是否影响已有验收 |
| next_action | 下一个明确动作；外部缺失输入写具体是什么 |

证据 → 发现 → 恢复路径应能追溯。静态推断和运行观察不能互换；原包与恢复包的相似输出也不能唯一证明内部实现。

只有局部材料时，下一工作单元仅代表当前证据支持的选择；不能声称已经排完全部项目优先级。状态摘要中的“构建通过”是既有记录，未见原始回执或未复跑时要注明，不升级为本次独立验证。

## 证据时效与证明边界

对冲突主张记下证据日期、输入版本、范围、被何项替代，以及当前源码是否仍存在该问题。复制时间不是实验时间；更新的局部回执不替代无关全局结论。旧审计可能同时包含已修缺口和仍有效限制，逐项处理，不整份继承或丢弃。需要现状统计时只读重算到独立输出位置，不覆盖历史回执。

明确每种检查的证明能力：

| 检查 | 能支持什么 / 还缺什么 |
|---|---|
| 输入哈希、token/地址/字段映射 | 确认依据身份；不证明源码语义正确 |
| 指令锚点、调用序列、源码模式检查 | 指定结构相符；可能未覆盖完整 CFG、数据流或状态 |
| 独立候选的行为测试 | 给定输入与替身下满足契约；不证明 Unity 适配与正式调用链 |
| 原实现与候选的差分 | 仅覆盖记录的输入、状态及副作用；检查 oracle 是否独立、原生调用是否被替换为共享假设 |
| 工程构建和正式运行 | 分别证明对应版本的构建与限定运行；不能自动推广未覆盖分支 |

报告计数时分开原始记录、唯一原生地址、共享/泛型别名、源码方法和独立策略片段；不相加成为“恢复方法数”。语法空壳扫描用于筛查，非空方法也不等于已证实行为。

源码当前快照与历史 APK 之间若缺输入清单或构建关联，标记“本包未提供该关联证据”；现有日志和局部文件哈希仍保留各自证明力。不要据此断言构建伪造，也不要把归档 manifest 误当构建输入 manifest。

## 选择有信息增益的验证

- 普通局部编辑不为数量写测试。高风险语义如字段接收者、SetParent、回调覆盖、取消/清理、保存边界，使用能分辨原/错实现的夹具。
- 夹具同时记录前置状态和副作用；通过人工注入/直接进关的夹具只证明局部契约，不证明正式入口。
- 修改 Shader 时，导入检查用于发现编译错误；GPU 读回/同节点画面对照才覆盖实际输出。无 GPU 条件时不伪造视觉通过。
- 修改业务链后，从原入口验证对应转换；已有不受影响基线继续有效，不无限重测前三关。
- 构建前后源码/资源变动有记录。最终包哈希关联运行日志；若安装包不匹配，不把旧运行记录转移到新源码。
- 例如 A 包已验收前三关、B 包仅编译通过：保留 A 的历史结论，B 的对应运行仍待验证；按 B 的变更影响决定回归范围，不自动把旧验收作废或移植。
- 核实日志的编译与输出链：同名 Debug、Conditional、符号、探针是否打包。缺日志只是观察缺失，不能直接推出没有收到输入。

只读审计可以报告静态确认与限定推断，不应为填写“运行验证”去启动被用户禁止的程序。实施任务则继续完成已授权且可独立推进的工作，不把可做的静态恢复留给用户批准。

## 防止无效循环与范围漂移

每次分析/构建/采集应有问题、判定条件和下一分支。反复失败而没有缩小原因时，回到最小依赖切片，校验版本、日志与契约；不要继续无目标堆日志、换工具或重建包。

在多个模块并行时，按不重叠文件或只读审计分工；只有原有授权允许时才启用子代理。每条结果携带输入版本、证据与未知项，集成由一处负责。不向其他用户会话发消息、不修改并行工程来“顺便修复”。

跨模块方向、交付承诺或长期流程变化按项目要求记录决策。技能自身不强制额外审批；已有授权和用户最新指令优先。

## 可读源码交付检查

- 工程可编辑，业务实现有明确命名和职责；诊断路径不混入正式启动语义。
- 必要原资产、GUID/绑定、官方依赖版本、设置、构建场景与工具命令自包含；不依赖别的会话工作目录。
- 匹配的构建产物与源码/资源版本可核对。若没有干净重建验证，明确说明，不能用归档校验代替。
- 可追溯语义账本和必要回归脚本齐备，不将反汇编噪声全部塞进代码注释。
- 交接写清当前范围、每层结果、最后有效回执、未完成项、下一动作和可用的运行条件。
- 不把重做美术的质量当原还原能力，不把排除范围悄悄计入完成分母，不自动 Git 提交或发布。
