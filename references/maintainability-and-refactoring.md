# 语义保持重构与可维护性验收

目标是让接手者能理解核心行为、找到修改位置并复验，同时保持约定范围内的原行为。可读性贯穿恢复；交付前检查剩余障碍，不等全部重建结束后再进行大规模清理。

## 切分范围

| 类别 | 处理方式 |
|---|---|
| 通用交付要求 | 核心业务命名与流程清楚，职责和副作用可定位，绑定兼容，必要说明及验证入口齐备 |
| 按问题选择的重构 | 提炼方法、统一已确认常量、抽取独立规则、隔离副作用、转换状态机；依据具体收益与风险选择，不强制统一架构 |
| 等价恢复修复 | 当前实现与原证据不符时补回原语义；记录原差异，不能包装为仅改可读性 |
| 产品扩展 | 新玩法、改变奖励或容错规则、额外开发工具、美术重做；依用户授权单独推进，不算等价覆盖 |

为构建、回归或后台验证所需的窄工具属于恢复支撑，不因含有调试功能被排除；额外产品工具不自动成为必交项目。

原行为中看似重复的通知、不合理的失败路径或可重入回调，不因“更健壮”就能顺手改变。新增锁、去重或 finally 清理可能改变时序与副作用：先确认原契约，再判定属于保持行为、修复恢复错误还是产品改变。

若项目已包含用户授权的扩展，保留它们及各自回执；记录等价基线与有意改变的范围，不为了验收重建第二套正式工程，也不擅自撤销功能。

## 按障碍小步改进

1. **确认基线与问题。** 读取当前源码版本和最后有效回执，选择一个具体障碍，如结算顺序难理解、规则混在 UI 副作用中。恢复版已有回归基线用于发现漂移，不能替代原版依据。用户只要评审时不实施。
2. **列出保持项。** 确认输入、状态、接收者、调用/求值顺序、事件、保存与生命周期；选出受影响的绑定和分支。未知语义先补依据，不用重构猜出业务。
3. **完成最小有效改动。** 方法命名表达业务步骤，注释解释不显然的顺序或约束；规则能独立时再抽取输入/输出契约。保持原组件入口，确保新 helper 被正式路径调用，避免产生只在测试中使用的平行实现。
4. **验证并同步证据。** 根据改动影响选择源码/引用检查、导入构建、规则夹具及正式流程回归；记录当前版本与仍未验证的层。更新项目既有任务卡、说明和回执索引，不另建总控系统。

## 需要保护的工程边界

- **Unity 身份与序列化。** 检查 MonoScript GUID/fileID、类型/程序集、字段、Prefab override、UnityEvent 与动画事件绑定。不能按文本替换直接改名；确需迁移时使用适合目标 Unity 版本的兼容方式，并核对实际场景、Prefab 和存档读取。保留身份不意味着禁止提炼普通私有方法。
- **异步与清理。** 转换 IEnumerator/async 时覆盖开始、继续、正常完成、取消、对象销毁、异常和 Dispose/清理路径。只读到状态名或仅测完成分支不足以确认等价；无法可靠验证的状态机先改善命名和局部结构。
- **职责与依赖。** partial 或目录拆分改善导航，但仍可能共享所有状态。根据修改需求提炼真正可独立理解的规则，明确谁读状态、谁写状态、谁产生 UI/存档副作用；不强制引入 DI 框架、asmdef、接口数量或文件行数门槛。
- **运行适配与诊断。** 按实际调用和构建条件识别必要的渲染/平台桥接。历史目录名带 Diagnostics、Experiment 或 CLI 不证明可删除；分清正式依赖与采集工具后再整理，公开 skill 不固化任何项目的历史类名或参数。
- **第三方与生成代码。** 可读性重点是正式业务链；不为消除扫描命中批量重写库、生成输出或合法迭代器行为。数字枚举和重复常量仅在含义及类型确认后替换。

## 有效验证与完成条件

规则夹具优先调用正式使用的实现，以能区分错误行为的边界和副作用验证；别在测试里复制一套同样公式。纯规则通过仍不证明 Unity 适配、绑定和正式入口通过。低影响编辑不为数量添加测试，也不因小改动无限重跑所有关卡。

重构后按影响重新判定旧回执的效力。源码字符串检查只证明接线线索；归档哈希只证明文件身份。不能用旧包的通过记录直接覆盖当前源码，也不将不受影响的历史结论全部作废。源码、构建和运行之间缺关联时，明确缺口。

检查工具要区分“收集问题”和“验收失败”：进入验收门禁的已确认关键缺脚本、断引用或 Shader 错误应使门禁失败；合法可选空引用和历史允许项注明理由与范围，不把全部 null 自动判失败。

在项目既有交接中提供足够信息，使接手者可以：

- 沿核心流程找到入口、状态推进、结算/保存及关键异步路径，理解必要顺序。
- 定位规则与副作用的修改边界，并知道绑定或兼容性约束。
- 使用包内源码、依赖与有效说明构建和复验；文档引用的当前材料可用，历史材料标明范围与获取方式。
- 对照当前版本的分层结果，分清等价恢复、语义保持重构、授权扩展与未知项。

满足这些要求且受影响的检查闭合后结束本阶段。若还有明确维护障碍，记录其影响与下一动作；不以零静态依赖、零手写状态机或所有文件低于某行数作为完成条件。无法运行时继续可独立的优化与静态核验，但保留行为未复验的限制，不宣称全范围无回归。
